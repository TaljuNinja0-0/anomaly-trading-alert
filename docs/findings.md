# 토이 프로젝트 결론 — 이상매매 탐지 4단계 로드맵 + 앙상블 검증

> 대상: `/home/user/bigdata-presentation/anomaly-trading-alert-plan.md` 6절 실습
> 아이디어의 실제 구현(`anomaly-trading-alert` 레포). 투자경고종목 지정 사례
> 4건(SK하이닉스, SK스퀘어, 현대로템, 두산에너빌리티 — 전부 2025년 12월,
> "최근 1년 200%+ 상승" 사유로 지정)으로 검증한 proof-of-concept이고,
> 정식 서비스가 아니다.

## 1. 4단계 로드맵 실데이터 결과

| 단계 | 구현 | 탐지(4건 중) | 과탐율 범위 |
|---|---|---|---|
| 1. 통계룰 | 거래량·가격 z-score 복합점수, `score > μ+2.5σ` | 1/4 (SK스퀘어, 22일 전) | 0~2.8% |
| 2. ML | IsolationForest, 100행 베이스라인, `contamination=0.05` | **4/4** | 2.8~19.4% |
| 3. DL | LSTM Autoencoder, 20일 시퀀스 재구성오차 | 1/4 (두산에너빌리티, 30일 전) | 0~11.1% |
| 4. 파운데이션 모델 | Chronos-bolt 인코더 임베딩, 베이스라인 중심점까지 코사인 거리 | **4/4** | 8.3~75%(종목별 편차 큼) |
| (검증) 앙상블 = 통계룰 ∪ ML | 두 단계의 탐지일을 합집합 | 4/4 (ML과 완전히 동일) | ML과 완전히 동일 |

소스: `output/results*.csv` (4건 모두 `status=ok`로 끝까지 계산됨 —
`insufficient_data`/`undetermined`로 빠진 사례 없음).

## 2. 핵심 발견: "더 복잡한 모델 = 더 잘 탐지"가 아니다

4건 전부 **몇 달에 걸쳐 서서히 쌓인 추세성 이상**이지, 하루짜리 급등락이
아니다. 이게 성능 차이를 가른 핵심 변수였다.

- **ML·파운데이션 모델(4/4)**: 100행짜리 넓은 베이스라인을 두고 "지금 이
  패턴이 평소 분포에서 얼마나 벗어났는가"를 다차원·전체적으로 비교하는
  방식 — 서서히 벗어나는 추세도 결국 "평소 분포 밖"으로 걸려든다.
- **통계룰(1/4)**: 당일 값을 직전 20일과만 비교 — 추세가 이미 "새로운
  평소"로 흡수돼버려서 놓친다.
- **DL/LSTM-AE(1/4)**: 똑같이 100행 베이스라인을 썼는데도 실패했다.
  진단해보니 관찰구간의 재구성오차가 오히려 베이스라인보다 **낮게**
  나왔다 — 서서히·매끄럽게 움직이는 추세는 시퀀스 재구성 모델 입장에서
  평소 노이즈보다 오히려 예측하기 쉬운 패턴이라, 역설적으로 "정상"으로
  판정된 것(상세: `src/dl_detector.py` 모듈 docstring).

즉 로드맵을 한 단계씩 고도화할수록 무조건 좋아진다는 가정은 이번
사례들에서는 틀렸다 — DL이 통계룰보다 나을 이유가 없었고, 가장 단순한
ML이 가장 잘 맞았다.

## 3. 앙상블(통계룰 ∪ ML) 검증 — "최선"이 증명되지는 않았다

사용자 제안("통계룰은 저비용·저과탐 급스파이크용, ML은 추세성 이상
전담 — 둘을 같이 돌리면 제일 실용적일 것")을 실제로 구현해서 검증했다.

**결과**: 4건 전부에서 앙상블 출력이 **ML 단독과 완전히 동일**했다. 통계룰이
탐지한 날짜(예: SK스퀘어의 145번째 거래일)는 항상 ML이 탐지한 날짜 집합의
부분집합이었다 — 합집합을 해도 추가되는 게 없었다.

**이게 "앙상블 아이디어가 틀렸다"는 뜻은 아니다.** 4건이 전부 같은
유형(추세형) 이상이라서, 통계룰의 진짜 강점(급격한 단일일 스파이크)을
시험해볼 사례 자체가 이번 검증 세트에 없었다. 가설의 절반(통계룰이
스파이크를 잡는다)은 **검증되지 않은 것**이지, 반증된 게 아니다.

## 4. 결론

- 4단계+앙상블 중 **명확한 최고 성능**은 ML(IsolationForest)이다 — 4/4
  탐지, 상대적으로 낮은 과탐율(2.8~19.4%), 추가 인프라(별도 conda
  환경) 불필요.
- 앙상블은 ML과 동률이지 ML보다 낫다는 근거는 이번 검증에서 안 나왔다.
  통계룰을 같이 돌리는 비용이 거의 0에 가깝다는 점(이미 계산하는 값)을
  감안하면 "손해볼 건 없다"는 근거로 포함은 할 수 있지만, "앙상블이
  최선이다"라고 단정할 근거는 아직 부족하다.
- **한계**: 사례가 4건뿐이고 전부 같은 유형(추세형)이라, 정밀도·재현율
  같은 정식 지표를 낼 수 없고, 통계룰의 강점 구간(급스파이크)은 아예
  검증되지 않았다. 실제 서비스로 확장하기 전에 급스파이크형 사례를
  최소 몇 건 추가로 검증해보는 게, 지금 상태로 바로 확장하는 것보다
  안전하다.

## 5. 다음 단계 (보류 — 사용자 결정 대기)

"토이 프로젝트에서 검증해보고 가장 좋다는 결론이 나면 시가총액 상위
200개로 실제 서비스를 확장한다"는 전제였는데, 위 3절 결과가 "앙상블이
확실히 최선"을 보여주지 못했으므로, 다음 중 하나를 사용자가 선택해야
한다:

1. 지금 결과(ML이 명확한 최고 성능, 앙상블은 동률)를 그대로 근거 삼아
   top-200 확장으로 진행 — 앙상블 자체는 손해가 없으니 포함.
2. 급스파이크형 투자경고 사례를 몇 건 더 찾아 통계룰의 강점을 실제로
   검증한 뒤 확장 여부를 재판단.
